## 1. 节点定位

L0.5 领域架构位于 L0(项目架构)与 L1(业务架构)之间,是**业务语义的标准化层**——把 L0 提到的 5 大闭环拆成**领域对象**(Aggregate)、**实体**(Entity)、**值对象**(Value Object)、**领域事件**(Domain Event)、**领域规则**(Invariant)。

## 3. 核心领域对象(按 Context 分组)

### 3.1 委托取样上下文(Sampling Context)

#### 3.1.1 `Sample`(聚合根)

**定义**: 客户送检的最小单位,具有唯一编号 `sampleNo`(格式 `YYMMDD-NNNN`)。

**字段**(核心):
| 字段 | 类型 | 说明 |
|---|---|---|
| sampleNo | String unique | 编号(日期 + 序号)|
| customerName | String | 客户名称 |
| sampleType | enum | GOLD_INGOT / JEWELRY / POWDER / ... |
| weightG | Decimal(15,6) | 重量 g |
| status | enum | RECEIVED → BATCHED → TESTED → REPORTED → ARCHIVED → DISPOSED |

**关系**:
- 1:1 → `SamplingRecord`(W4,可空,客户送样可无取样记录)
- 1:1 → `PreciousMetalBar`(W4,检测完成后生成)
- N:1 → `User`(receivedById)
- N:1 → `Method`(methodId)
- N:1 → `SampleBatch`(batchId,可空)

**缺口**:
- ❌ 没有 `Sample.receivedAt` 校验不能晚于当前时间
- ❌ 没有 `Sample.storageLocation`(暂存在哪)
- ❌ 没有 `Sample.chainOfCustody`(监管链说明;只有 SamplingRecord 有)

#### 3.1.2 `SamplingRecord`(实体,W4)

**定义**: 取样现场凭证,记录「谁、何时、何地、怎么取的」。

**字段**(核心 26):见 schema.prisma。

**关系**:
- 1:1 → `Sample`(sampleId,可空)
- N:1 → `User`(sampledById)

**缺口**:
- ❌ 没有 `photoFileIds` 关联到 `FileAttachment`(字段存了 UUID 但没外键)
- ❌ 没有 `sealNumber` 数字签名(SHA256 + 数字证书)防止篡改

---

### 3.2 检测执行上下文(Testing Context)

#### 3.2.1 `Test`(聚合根)

**定义**: 单个样品的某次检测任务,带方法 / 操作员 / 起始完成时间 / 纯度结果 / 不确定度。

**字段**(核心 14):
| 字段 | 类型 | 说明 |
|---|---|---|
| sampleId | FK | 必填 |
| batchId | FK? | 可空 |
| method | enum | FIRE_ASSAY / ICP_OES / GRAVIMETRY / VOLUMETRY |
| startedAt / completedAt | DateTime | 检测起止 |
| operatorId | FK? | 操作员 |
| purityPct | Decimal(10,6) | 主元素纯度(Au99.99%) |
| uncertainty | Decimal(10,6) | k=2 扩展不确定度 |
| qcPassed | Boolean? | QC 通过标记 |

**关系**:
- N:1 → `Sample`
- N:1 → `User`(operator)
- 1:N → `ElementResult`(W1 后所有杂质元素)
- 1:1 → `FireAssayDetail`(火试金法时)
- 1:N → `QcMeasurement`(QC 平行样 / 空白 / 加标)

**关键业务规则**:
- R-T-01:`completedAt` 必须 ≥ `startedAt`
- R-T-02:`purityPct` ∈ [0, 100],不允许 ≤ 0
- R-T-03:`uncertainty` 必须 ≥ 0
- R-T-04:`qcPassed = false` 的 Test 不能进入报告生成

**缺口(关键 — 评审必问)**:
- ❌ **`uncertainty` 字段无来源说明** — 不确定度是手填还是自动算?
- ❌ **无 `uncertaintyReportId` 外键**(Phase 1B 待补)
- ❌ **无 `calculationFileId`** 计算附件(GUM Workbench 输出)
- ❌ **无 `methodId` 外键**(只有 `method` enum 字符串)
- ❌ **无 `rejectedReason`** OOS 标记
- ❌ **无 `methodVersion`** 方法版本号(可能 V1 vs V2 给出不同结果)

#### 3.2.2 `ElementResult`(实体)

**定义**: ICP-OES 等多元素分析时的单元素结果(黄金中 Cu / Fe / Pb / Ag 等杂质)。

**字段**(核心 12):
- `testId`, `element` (Au/Ag/Cu/Fe/Pb/Pt/Pd)
- `concentration` (主), `lod` / `loq` (检出限 / 定量限)
- `uncertainty` (单元素)

**缺口**:
- ❌ 没有 `wavelengthNm`(当前有,但常被忽略)— 应作为必填
- ❌ 没有 `isStandardCurveValid`(校准曲线是否过验证)
- ❌ 没有 `standardRecovery`(与标准物质比对回收率)

---

### 3.3 质量控制上下文(QC Context)

#### 3.3.1 `QcMeasurement`(实体)

**定义**: 单次质控测量(平行样 / 空白样 / 加标回收 / 质控样),带 Westgard 规则判断。

**字段**(核心 16):
- `testId`, `element`, `measured`, `expected`, `sd`
- `zScore`, `recoveryPct`, `westgardRule`, `passed`
- `referenceId` (FK → ReferenceMaterial), `operatorId`

**关键规则**:
- R-QC-01:Westgard 规则应用应系统化(目前字段是字符串,需补充 `appliedRule` 自动判定字段)
- R-QC-02:`passed = false` 应触发 OOS(OOS 未建模,缺口)

**缺口**:
- ❌ **`passed` 字段自动计算** — 当前服务业务写入 `passed: true`,没真算 Westgard
- ❌ **无 `violatedRule` 字段**(westgardRule 存的是规则名)
- ❌ **无 `consecutiveFailures` 字段** — 4-1s / 10-x 规则需要连续多次结果
- ❌ **无 `controlMaterialLot` 字段** — QC 样品批号溯源
- ❌ **`QcMeasurement.referenceId` 无外键约束**(字段存 UUID 但 Prisma 没声明)

#### 3.3.2 `ReferenceMaterial`(实体)

**定义**: 标准物质,有证标准物质(CRM)或工作标准物质。

**字段**(核心 12):
- `code`(如 GBW02757), `element`, `certifiedPct`, `uncertainty`
- `manufacturer`, `receivedDate`, `expiryDate`

**关键规则**:
- R-RM-01:`expiryDate` < now 时**禁止使用** — 当前**无系统级阻断**
- R-RM-02:应有证书 PDF 原件(SHA256) — 当前无

**缺口(Phase 1B 重点)**:
- ❌ **`sha256Certificate` 字段缺失** — 证书防伪
- ❌ **`standardUncertainty` 字段缺失** — 标准 U(k=2)
- ❌ **`isCrm` 字段缺失** — 区分有证 vs 工作
- ❌ **`nextVerificationDate` 缺失** — 期间核查计划
- ❌ **`storageLocation` / `storageTemp` 缺失** — CRM 保管条件
- ❌ **`ReferenceMaterialUsage` 表缺失** — 每条 ElementResult 用哪个 RM?领了哪瓶?

---

### 3.4 报告签发上下文(Reporting Context)

#### 3.4.1 `Report`(聚合根)

**定义**: 单个样品的正式检测报告。

**字段**(核心):
- `reportNo`(RPT-{sampleNo}), `sampleId`, `status`
- `summary`(报告内容), `pdfSha256`, `issuedAt`

**状态机**:`DRAFT → INTERNAL_REVIEW → FINAL_REVIEW → APPROVED → ISSUED → SUPERSEDED`

**关系**:
- N:1 → `Sample`
- 1:N → `ReportStage`(每阶段一条)
- 1:N → `ReportSignature`(三级签字)

**关键规则**:
- R-R-01:`ISSUED` 后不可修改
- R-R-02:`ISSUED` 时必须有 3 个 Signature(起草 / 校核 / 批准)

**缺口**:
- ❌ **无 `recalledAt` 字段** — 报告召回机制
- ❌ **无 `clientFeedbackAt`** — 客户反馈留痕

#### 3.4.2 `ReportStage` + `ReportSignature`

**ReportStage**:5 阶段记录,每阶段一条 stage + userId + comments。
**ReportSignature**:数字签名(MFA-TOTP 生成),不可篡改。

**缺口**:
- ❌ **`ReportStage` 缺少 `signedAt`** 时间字段(只能从 createdAt 推断)
- ❌ **`ReportSignature.signatureHash` 缺少冗余签名(应至少 2 人 + 时间戳 + 内容)

### 3.5 设备设施上下文(Facility Context)

#### 3.5.1 `Equipment`(聚合根)

**定义**: 物理设备(天平 / ICP / 火试金炉 / 干燥箱等)。

**字段**(20):
- `equipmentNo`, `type`, `model`, `location`, `status`

**关系**:
- 1:N → `Calibration`(校准证书)
- 1:N → `Maintenance`(维护记录)
- 1:N → `PeriodicCheck`(期间核查)

**关键规则**:
- R-E-01:`status = RETIRED` 的设备**不可被检测引用**
- R-E-02:`nextDueDate < now` 应告警

#### 3.5.2 `Calibration`(实体)

**字段**(10):`calibrationDate`, `calibrationOrg`, `certificateNo`, `nextDueDate`, `result`

**缺口**:
- ❌ **`certificateFileId` 字段已有但未关联 FileAttachment** — 应建外键
- ❌ **无 `calibrationType`** — 内部 / 外部 / 厂家

#### 3.5.3 `Container`(W3,实体)

**字段**(24):`code`, `type`, `material`, `capacityMl`, `toleranceMl`, `toleranceClass`, `status`

**状态机**:`IN_STOCK → IN_USE → (CLEANING / MAINTENANCE) → IN_STOCK / RETIRED`

**缺口**:
- ❌ **`Container.calibrationDate` 缺** — 容量瓶应定期校准
- ❌ **当前有 `nextCalDate` 字段,但无系统级告警钩子**

#### 3.5.4 `Gas`(W2,实体)

**字段**(22):`code`, `type`, `currentStock`, `minStock`, `maxStock`

**缺口**:
- ❌ **`reorderPoint` 字段缺失** — 自动补货阈值
- ❌ **当前 `minStock` 与告警耦合**,但无自动采购单生成

**缺口**:

## 4. 共享内核(Shared Kernel)

跨上下文的 MinIO 文件指针:`sha256`, `category`, `storagePath`

## 5. 领域事件清单(13 种 AuditEventType)

| 事件 | 触发场景 | 关键字段 |
|---|---|---|
| AUTH:LOGIN_SUCCESS | 登录成功 | userId, ip |
| AUTH:LOGIN_FAILED | 登录失败 | userId, reason |
| AUTH:ACCOUNT_LOCKED | 连续失败锁定 | userId, count |
| SECURITY:ACCESS_DENIED | RBAC 403 | userId, resource |
| SECURITY:BRUTE_FORCE_ATTEMPT | 登录爆破 | ip, count |
| SECURITY:AUDIT_TAMPER_ATTEMPT | 审计篡改 | userId, table |
| SECURITY:SENSITIVE_ACCESS | 敏感数据(审计导出)| userId, action |
| SYSTEM:START | 服务启动 | version |
| SYSTEM:SHUTDOWN | 服务关闭 | — |
| CONFIG:PERMISSION_CHANGED | 角色权限变更 | operatorId, targetId |
| CONFIG:SETTINGS_CHANGED | 系统参数变更 | operatorId, key |

**缺口(W5 新增的):**
- `REALTIME:WASTE_TRANSFERRED` / `WASTE_DISPOSED` — 危废事件推送
- `REALTIME:GAS_LOW_STOCK` — 气体低库存
- `REALTIME:CONTAINER_BORROWED` — 容器领用
- `REALTIME:BAR_CERTIFIED` — 贵金属条码出证

> **建议**:**AuditEventType 与 RealtimeEventType 应区分** — Audit 是合规证据,Realtime 是 UX 推送,但**所有 Realtime 应同时写 Audit**(W5 部分实现)

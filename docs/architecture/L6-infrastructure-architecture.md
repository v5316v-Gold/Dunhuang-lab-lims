## 1. 节点名称

**L6-基础设施架构**(Infrastructure Architecture / 部署与基础设施)

## 2. 建设目标

1. 定义**部署拓扑**(开发 Compose / 生产 K8s)
2. 定义**环境管理**(dev/staging/prod 隔离)
3. 定义**高可用与灾备**(RPO ≤ 1h / RTO ≤ 4h)
4. 定义**安全基线**(等保 2.0 二级,网络/加密/审计)
5. 定义**存储与备份**(3-2-1 策略)
6. 为 L8 运维提供监控/恢复基础

## 3. 业务范围

- **In-scope**:
  - 容器与编排(Compose → K8s 演进)
  - 网络(端口/隔离/DMZ)
  - 数据库/缓存/文件存储基础设施
  - 备份/恢复/灾备
  - 安全基线(等保 2.0)
- **Out-of-scope**:
  - 具体运维执行 → 归 L8
  - 技术选型理由 → 归 L5/ADR-0008

## 4. 背景

当前开发环境:Docker Compose(`dunhuang-pg` TimescaleDB 55432:5432、`dunhuang-redis` 56379:6379),与 `dunhuang-ai` 项目端口隔离。生产目标:K8s(参考 ADR-0008 kind/k3d)。`docs/05-DEPLOYMENT.md` 已有部署设计。本层将基础设施**固化为架构规范**,重点解决端口管理、环境隔离、备份与安全。

## 8. 业务流程

部署流程(文字描述):

```
代码提交 → CI 构建(测试+lint)→ 镜像构建 → 推送 registry
  → 部署(staging 验证)→ 生产发布(滚动/蓝绿)→ 健康检查 → 回滚预案
```

## 12. 业务规则

| 编号 | 规则 | 可测试性 |
|---|---|---|
| BR-INF-01 | 开发与生产环境完全隔离 | 端口/网络检查 |
| BR-INF-02 | 备份 3-2-1(3 份/2 介质/1 异地) | 备份清单 |
| BR-INF-03 | 生产数据库必须主备 | 拓扑检查 |
| BR-INF-04 | 密钥不落代码仓库 | secret 管理检查 |
| BR-INF-05 | 端口最小暴露(仅 443/80) | 安全扫描 |
| BR-INF-06 | 容器只读文件系统(生产) | 安全基线 |
| BR-INF-07 | TLS 强制(生产) | 证书检查 |
| BR-INF-08 | RPO ≤ 1h / RTO ≤ 4h | DR 演练 |

## 13. 异常处理

| 异常场景 | 检测方式 | 响应策略 |
|---|---|---|
| 容器崩溃 | health check | 自动重启/副本替换 |
| 端口冲突 | 启动失败 | 端口规划表 + 检测 |
| 磁盘满 | 监控 | 清理/扩容 |
| 证书过期 | 监控 | 自动续期/告警 |
| 节点故障 | 编排 | 自动调度 |
| 数据损坏 | 备份校验 | 恢复演练流程 |

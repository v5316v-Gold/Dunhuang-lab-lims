## 1. 节点名称

**L0-项目架构**(Project Architecture / 项目级治理架构)

## 2. 建设目标

1. 定义项目章程:定位、愿景、边界、承诺("5 个零")
2. 固化干系人图谱与 RACI 决策机制
3. 定义顶层 WBS、里程碑(M1-M6)与验收标准
4. 建立项目级风险登记册与变更控制机制
5. 为 L0.5 领域架构提供业务边界与术语基线

## 3. 业务范围

- **In-scope**:
  - 项目章程(愿景/目标/边界)
  - 干系人、角色与决策机制
  - 顶层 WBS 与里程碑
  - 项目级风险与变更控制
  - 文档治理(ADR/规范/版本)
- **Out-of-scope**:
  - 业务流程细节 → 归 L1 业务架构
  - 领域建模 → 归 L0.5 领域架构
  - 法规条款落地 → 归 L2 合规架构

## 4. 背景

敦煌金质检 LIMS 已完成 Phase 0(基座)+ Phase 0.5(Baseline Hardening,25/25 测试 PASS)。系统已具备可运行骨架,但**项目级治理尚未文档化**:章程、干系人 RACI、风险登记册、变更控制均分散在 `00-PROJECT-PLAN.md`、`06-ROADMAP.md`、`PROJECT-STATUS.md` 中。本层将项目治理统一固化,作为全部架构规范的第一层基座。

依据:
- `docs/00-PROJECT-PLAN.md`(愿景/KPI/范围/角色/成本/验收)
- `docs/06-ROADMAP.md`(13 周路线图,M1-M6)
- `docs/PROJECT-STATUS.md`(当前状态)
- `docs/execution/PHASE-0.5-RESULT.md`(Phase 0.5 GATE PASS)

## 8. 业务流程

项目治理流程(文字描述):

1. **立项**(已完成):愿景定义 → 范围确认 → 资源承诺 → 章程草案
2. **规划**:顶层 WBS → 里程碑 M1-M6 → 风险登记册 → 文档治理规则
3. **执行**:Phase 0/0.5 已执行;Phase 1-5 按 06-ROADMAP 推进
4. **监控**:每周站会/评审 → 风险更新 → KPI 追踪 → 管理评审(月度)
5. **收尾**:CNAS 现场评审(2026-11-03)→ 验收 → 移交运维(L8)

## 9. 状态机

### 9.1 项目生命周期

| 状态 | 含义 | 进入事件 | 离开事件(目标) | 守卫条件 |
|---|---|---|---|---|
| INITIATING | 立项 | 管理评审批准 | 章程定稿 → PLANNING | 范围/预算/资源确认 |
| PLANNING | 规划 | 章程定稿 | WBS 评审通过 → EXECUTING | 里程碑可追踪 |
| EXECUTING | 执行 | 计划批准 | Phase gate 全 PASS → MONITORING | 各 Phase 验收 |
| MONITORING | 监控 | 首轮评审 | 风险可控/偏差关闭 → EXECUTING | 偏差 CAPA 闭环 |
| CLOSING | 收尾 | CNAS 评审通过 | 移交运维 → 完成 | 验收报告批准 |

## 12. 业务规则

| 编号 | 规则 | 可测试性 |
|---|---|---|
| BR-L0-01 | 范围变更须经管理评审并记录 CR | 检查变更记录 |
| BR-L0-02 | 里程碑延期 > 1 周须上报决策层并更新风险登记册 | 检查里程碑状态+风险日志 |
| BR-L0-03 | 架构决策必须落 ADR(编号连续) | 检查 docs/adr/ 完整性 |
| BR-L0-04 | 任何 Phase 启动前,上一 Phase GATE 必须 PASS | 检查 PHASE-*-RESULT.md |
| BR-L0-05 | 代码提交遵循约定式提交(commit message 规范) | git log 检查 |

## 13. 异常处理

| 异常场景 | 检测方式 | 响应策略 | 升级路径 |
|---|---|---|---|
| 范围蔓延 | 里程碑/需求变更频繁 | 变更控制 + 影响分析 | 管理评审 |
| 关键延期 | 里程碑 AT_RISK | 资源重排/范围裁剪 | 决策层 |
| 预算超支 | 月度财务审查 | 成本削减计划 | 管理层 |
| 关键技术失败 | ADR 修订/故障 | 备选方案评审 | 架构师+决策层 |
| 合规缺口 | 内审/预审发现 | CAPA 闭环 | QA Manager |

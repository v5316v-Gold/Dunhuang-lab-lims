## 1. 节点名称

**L7-验证架构**(Validation Architecture / CSV 验证体系)

## 2. 建设目标

1. 固化 **GAMP 5 分类判定**(G1-G5)与 V-Model 文档体系
2. 定义**测试策略**(单元/集成/E2E/性能)
3. 定义 **IQ/OQ/PQ 计划**与执行标准
4. 定义**验证证据链管理**(需求→用例→结果→代码版本)
5. 固化**验证状态与缺陷流程**
6. 为 CNAS 现场评审(2026-11-03)提供证据框架

## 3. 业务范围

- **In-scope**:
  - 全系统验证(后端/前端/DB/触发器/集成)
  - 自动化测试(jest 25 项 + 新增)
  - 人工验证(UAT/IQ/PQ)
  - 缺陷管理与回归
- **Out-of-scope**:
  - 运维复核执行 → 归 L8
  - 具体合规机制设计 → 归 L2

## 4. 背景

Phase 0.5 已建立验证基础:25 个 jest 集成测试 PASS、`docs/validation/VMP.md`(GAMP 5 分类)、`FMEA-risk-assessment.md`(48 风险)、`periodic-review-plan.md`。本层将验证体系**固化为架构规范**,明确 V-Model 文档职责与测试分层。

## 8. 业务流程

验证流程(文字描述):

```
需求(URS/FS)→ 用例设计(可追溯 RTM)→ 环境准备(IQ)
  → 执行(OQ:自动化+手工)→ 缺陷记录 → 修复回归
  → 性能(PQ)→ 验证总结(VSR)→ 证据归档
```

## 9. 状态机

### 9.1 用例生命周期

| 状态 | 含义 | 进入事件 | 离开事件(目标) |
|---|---|---|---|
| DRAFT | 草稿 | 用例设计 | 评审 → REVIEWED |
| REVIEWED | 已评审 | 评审通过 | 执行 → EXECUTED |
| EXECUTED | 已执行 | 执行开始 | 结果 → PASSED/FAILED |
| PASSED | 通过 | 符合期望 | 归档 → CLOSED |
| FAILED | 失败 | 不符合 | 缺陷 → 修复回归 |
| CLOSED | 关闭 | 缺陷闭环 | — |

### 9.2 缺陷生命周期

OPEN → TRIAGED → FIXING → VERIFIED → CLOSED / REOPENED

## 11. 字段(测试用例关键字段)

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 用例 ID | string | 是 | 格式:TC-<模块>-<序号> |
| 前置条件 | text | 是 | 环境/数据准备 |
| 步骤 | list | 是 | 可执行步骤 |
| 期望结果 | text | 是 | 断言 |
| 实际结果 | text | 否 | 执行后填写 |
| 结果 | enum | 是 | PASS/FAIL/BLOCKED |
| 关联需求 | string | 是 | RTM 追溯 |

## 12. 业务规则

| 编号 | 规则 | 可测试性 |
|---|---|---|
| BR-V-01 | 缺陷修复必须回归测试 | 回归检查 |
| BR-V-02 | 验证证据与代码版本绑定(commit hash) | 报告检查 |
| BR-V-03 | P1 缺陷不得上线 | 发布门禁 |
| BR-V-04 | 所有业务写路径必须有测试覆盖 | 覆盖率报告 |
| BR-V-05 | 审计链/防篡改测试每次变更后重跑 | CI 集成 |
| BR-V-06 | 测试数据与生产数据隔离 | 环境检查 |

## 13. 异常处理

| 异常场景 | 检测方式 | 响应策略 |
|---|---|---|
| 环境不可用 | 测试前置失败 | 环境修复/重建 |
| 测试数据污染 | 用例互扰 | 独立数据 + 清理 |
| 用例 flaky | 偶发失败 | 隔离 + 根因分析 |
| 缺陷复现不了 | 无法重现 | 记录环境/证据/暂挂 |

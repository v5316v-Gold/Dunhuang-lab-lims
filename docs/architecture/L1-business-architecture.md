## 1. 节点名称

**L1-业务架构**(Business Architecture / 业务流程与组织架构)

## 2. 建设目标

1. 定义**端到端业务流程**(委托→报告→归档)及各泳道职责
2. 固化**组织角色矩阵**(谁做什么,含 CNAS 关键岗位)
3. 定义**业务单据**及其流转关系
4. 沉淀**流程级业务规则**(≥ 15 条,可测试)
5. 定义流程异常路径与升级机制
6. 为 L2 合规映射、L4 模块实现提供流程规格

## 3. 业务范围

- **In-scope**:
  - 主流程:委托登记 → 样品接收 → 批次编排 → 检测执行(火试金/ICP)→ 质控 → 报告签发 → 客户交付 → 留样归档
  - 支撑流程:投诉处理、分包、能力验证、不符合工作处理
  - 组织与岗位:实验室主任/质量负责人/检测员/审核员/授权签字人/设备管理员/试剂管理员
- **Out-of-scope**:
  - 合规机制设计 → 归 L2 合规架构
  - 数据字典 → 归 L3 数据架构
  - 接口契约 → 归 L4 应用架构

## 4. 背景

L0.5 领域架构已定义 10 个限界上下文与聚合。本层将领域对象**编排为可执行流程**,明确每步的输入、角色、规则与异常。当前系统已实现主流程骨架(垂直切片 E2E 已验证:auth→sample→batch→fire-assay→qc→audit),本层将该骨架规范化为完整业务架构。

## 8. 业务流程

### 8.1 主流程(委托→报告→归档)

文字描述(泳道:客户 / 前台 / 样品室 / 检测组 / 质控 / 报告组 / 质量经理):

1. **委托登记**(前台):客户提交委托单(纸质/电子)→ 合同评审(能力范围、方法、周期、价格)→ 确认 → 生成委托号
2. **样品接收**(样品室):实物核对 → 拍照存档 → 编号(`YYMMDD-NNNN`)→ 称重 → 状态 RECEIVED
3. **批次编排**(检测组):按方法(火试金/ICP)组批 → 分配检测员 → 状态 BATCHED
4. **检测执行**(检测组):称样(≥3 平行样)→ 火试金工艺(熔融→灰吹→分金→退火→称重)或 ICP 消解→测定 → 记录原始数据 → 状态 IN_TEST
5. **质控验证**(质控):空白样/平行样 RSD/加标回收/QC 样回收率 → Westgard 规则评估 → 状态 TESTED 或 QC_FAILED
6. **数据校核**(检测组):结果复核 → 计算纯度/不确定度 → 状态 REPORT_DRAFT 准备
7. **报告起草**(报告组):生成报告(模板)→ 状态 DRAFT
8. **多级审核**(质量经理/授权签字人):一级审核(数据完整性)→ 二级审核(合规性)→ 三级签发(电子签名+时间戳)→ 状态 APPROVED/SIGNED
9. **客户交付**(前台):报告交付(纸质/电子)→ 签收记录
10. **留样归档**(样品室):留样 ≥6 个月 → 到期处置(销毁记录)→ 状态 ARCHIVED

### 8.2 支撑流程

- **投诉处理**:客户投诉 → 登记 → 调查 → 反馈 → 关闭(CNAS §7.9)
- **不符合工作**:检测过程发现不符合 → 停止/纠正 → 复测 → 记录(§7.10)
- **分包**:超出能力 → 分包评估 → 分包 → 结果合并(§6.5 外部服务)
- **能力验证**:PT 计划 → 参加 → 结果评估 → 改进

## 9. 状态机

### 9.1 业务单据流转

| 单据 | 状态序列 | 守卫 |
|---|---|---|
| 委托单 | DRAFT → CONFIRMED → IN_PROCESS → COMPLETED / CANCELLED | 能力范围校验 |
| 样品 | RECEIVED → BATCHED → IN_TEST → TESTED → REPORT_DRAFT → REPORT_REVIEW → REPORT_APPROVED → ARCHIVED / REJECTED | 状态只能顺序流转 |
| 批次 | PENDING → MIXING → FUSING → CUPELLING → PARTING → ANNEALING → WEIGHING → CALCULATING → COMPLETED / REJECTED | 平行样 ≥3 |
| 报告 | DRAFT → REVIEW → APPROVED → SIGNED → DELIVERED / REJECTED | 三级审核 |
| 投诉 | OPEN → INVESTIGATING → RESPONDED → CLOSED | 时限内关闭 |

## 10. 数据模型

业务单据模型(实体级):

| 单据 | 关键实体 | 关系 |
|---|---|---|
| 委托单 | 委托信息(客户/方法/要求) | 1:1 样品组 |
| 样品卡 | Sample(编号/重量/状态) | 1:N 检测任务 |
| 检测任务单 | Test + FireAssayDetail/ElementResult | 1:1 样品 |
| QC 记录 | QcMeasurement(类型/结果/判定) | 关联检测 |
| 报告 | Report + ReportStage + ReportSignature | 1:1 样品 |

## 12. 业务规则

| 编号 | 规则 | 来源 | 可测试性 |
|---|---|---|---|

## 13. 异常处理

| 异常场景 | 检测方式 | 响应策略 | 升级路径 |
|---|---|---|---|
| 样品异常(破损/信息不符) | 接收检查 | 拒收/待定 + 记录 | 质量经理 |
| 仪器故障 | 设备状态 | 换设备/停线 | 设备管理员 |
| 检测结果 QC 失败 | RSD/回收率 | 复测 + 偏差调查 | 质量经理 |
| 报告退改 | 客户反馈 | 退改流程(留痕) | 报告组 |
| 客户加急 | 委托单标记 | 加急审批 | 管理层 |
| 投诉升级 | 投诉时限 | 升级处理 | 质量经理 |

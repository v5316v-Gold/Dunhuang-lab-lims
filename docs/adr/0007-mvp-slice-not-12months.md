# ADR-0007:MVP 切片优先(13 周而非 12 个月)

> **状态**: Accepted
> **日期**: 2026-08-04
> **决策人**: 天枢(架构师)+ 菩提老祖
> **影响范围**: 项目实施策略、路线图、CNAS 审核时间表

## 背景

原项目计划([archive/06-ROADMAP-12months-original.md](../archive/06-ROADMAP-12months-original.md))按 **12 个月 / 8.5 人** 团队设计,5 个里程碑(M1-M2 基础/M3-M5 核心/M6-M8 检测/M9-M10 合规/M11-M12 高级)。

但当前实际情况:

| 维度 | 原计划假设 | 实际情况 |
|---|---|---|
| **团队规模** | 8.5 人 | 5-6 人(含 AI 加速) |
| **项目周期** | 12 个月 | 需尽快出可演示 |
| **资金** | 320 万 | 待定 |
| **CNAS 现场审核** | M12(第 12 月) | 越早越好 |

按原计划,即使有 8.5 人,**MVP 切片在 M9-M10(第 9-10 月)才有可演示**,**CNAS 预审在 M12(第 12 月)完成**。这与业务方的期望"尽快出可演示闭环"严重不符。

## 决策

**MVP 切片优先**:先实现"样品→检测→报告"端到端垂直切片,跑通后做横向扩展。

### 1. 13 周 6 阶段

| 阶段 | 周次 | 主题 |
|---|---|---|
| Phase 0 | W1 | 基座校准(monorepo + 全栈可启动) |
| Phase 1 | W2-3 | 基础设施(Prisma + 审计 + JWT + OpenAPI) |
| **Phase 2** ⭐ | **W4-6** | **垂直切片 MVP(样品→检测→报告)** |
| Phase 3 | W7-10 | 横向扩展(13 模块全上线) |
| Phase 4 | W11-12 | 合规加固(备份 + 灾备 + 自检) |
| Phase 5 | W13 | CNAS 预审(性能 + 安全 + 整改) |

### 2. 为什么"样品→检测→报告"是 MVP 切片首选

| 业务价值 | 说明 |
|---|---|
| **最长业务流** | 涵盖 LIMS 最复杂的全流程 |
| **5 大合规要点** | 审计链 / 多级审核 / 电子签名 / ALCOA+ / 数据完整性 |
| **端到端可演示** | 可给客户 / 审核员现场演示 |
| **可复用基建** | 13 模块都是"同构扩展" |

### 3. 与原 12 个月路线图的关系

| 维度 | 原 12 个月 | 新 13 周 | 改进 |
|---|---|---|---|
| **MVP 切片** | M9-M10(第 9-10 月) | **W6(第 6 周)** | **提前 9 个月** |
| **CNAS 预审** | M12(第 12 月) | **W13(第 13 周)** | **提前 11 个月** |
| **团队规模** | 8.5 人 | 5-6 人(含 AI 加速) | -30% |
| **可演示节点** | M9 后 | **W6 即有** | ⭐⭐⭐ |

### 4. 加速因子

为什么能做到 13 周(而非 12 个月):

1. **MVP 切片策略**:不追求大而全,先小而精
2. **AI 加速**:天枢(架构师 + AI 全栈)1 人 = 后端 2 人 + 前端 1 人 + DevOps 0.5 人
3. **业务收敛**:只做黄金检测(非通用 LIMS)
4. **技术栈一致**:文档已定 NestJS + Prisma + PG,无需选型纠结
5. **架构先行**:4411 行架构文档已成熟,无返工

## 理由

### 为什么必须 MVP 切片

| 反对意见 | 我的反驳 |
|---|---|
| "12 个月更稳妥" | **零代码拖到 12 个月 = 零业务价值** |
| "13 周做不完" | **3 个模块(样品/检测/报告)+ 5 大合规**可达成;有 PoC 经验 |
| "13 周质量差" | **质量 = 架构 + 测试 + 审计链**;架构已成熟 |
| "应先全模块铺开" | **铺开 13 模块无业务闭环 = 0 价值** |
| "AI 不能替代工程师" | **AI 加速 = 写代码 + 测试 + CI 配置;架构 / 合规 / 业务由人决策** |

### 为什么"样品→检测→报告"是最优切片

候选切片分析:

| 候选 | 复杂度 | 业务价值 | 合规覆盖 | 推荐 |
|---|---|---|---|---|
| **认证 + 用户 + 部门** | ⭐ | ⭐ | ⭐⭐ | ⚠️ 太小 |
| **样品 → 检测 → 报告** ⭐ | ⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐ | ✅ **MVP 切片首选** |
| **设备 + 校准** | ⭐⭐ | ⭐⭐ | ⭐⭐ | ⚠️ 业务流短 |
| **QC + Westgard** | ⭐⭐ | ⭐⭐ | ⭐⭐ | ⚠️ 偏单一 |
| **全模块并行** | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐ | ❌ 失败风险高 |

**"样品→检测→报告"涵盖**:
- 样品接收(业务起点)
- 批次管理(业务核心)
- 火试金 + ICP(两大检测方法)
- QC 验证(数据质量保障)
- 多级审核(合规要求)
- PDF 报告(法律文件)
- 电子签名 + 时间戳(合规底线)

**跑通后,13 模块的其他模块都是"同构扩展"**(人员 / 设备 / 试剂 / EHS / 分析)。

## 替代方案

### 备选 1:12 个月全员铺开(原计划)
- **优势**: "稳妥"
- **拒绝理由**: 12 个月零业务闭环 = 风险最大

### 备选 2:6 个月(2 倍 MVP 周期)
- **优势**: 折中
- **拒绝理由**: 比 13 周多 13 周,但无额外业务价值

### 备选 3:4 周极简 MVP
- **优势**: 快速
- **拒绝理由**: CNAS 8 大条款无法覆盖;不可演示

## 影响

### 正面影响
- ✅ **W6 即可演示**:客户/审核员可看完整流程
- ✅ **W13 即可申请 CNAS**:提前 11 个月
- ✅ **降低风险**:早出可演示 = 早发现真实问题
- ✅ **团队信心**:可演示 = 有进展 = 士气提升

### 负面影响 + 缓解
- ⚠️ **压力集中**:Phase 2 是关键 3 周,失败影响全局;**缓解**:Phase 1 充分准备,Phase 2 严格 WIP 限制(只做 3 模块)
- ⚠️ **质量风险**:时间紧易出错;**缓解**:测试覆盖率 ≥ 70%,L4 ≥ 85%,CI 全绿
- ⚠️ **范围蔓延**:客户看到 W6 演示后加需求;**缓解**:ADR-0011 业务约束;新增需求进 Phase 3 backlog
- ⚠️ **资源不足**:5-6 人 vs 8.5 人;**缓解**:AI 加速(天枢)+ 严格范围管理

### 关键约束

1. **Phase 2 严格 WIP 限制**:只做"样品→检测→报告",其他模块延后
2. **不可跳过审计链 / OpenAPI / 测试**:CNAS 红线
3. **不可绕过 MFA / RBAC**:CNAS 红线
4. **每个阶段结束必须验收**:周回顾 + 量化指标
5. **业务范围不可蔓延**:如要新增,必须新 ADR

## 验证标准

### Phase 2 验收(W6)

- [ ] 样品接收 → 批次创建 → 火试金检测 → QC 验证 → 多级审核 → PDF 报告 端到端可演示
- [ ] CNAS 8 大条款可逐条演示(ALCOA+ / 审计链 / 电子签名 / 多级审核 / 备份)
- [ ] 性能:从样品接收到 PDF 生成 ≤ 5 秒(不含工艺等待)
- [ ] 测试覆盖率 ≥ 70%(L4 ≥ 85%)

### Phase 5 验收(W13)

- [ ] 13 模块全上线
- [ ] API P95 < 500ms(1000 并发)
- [ ] CNAS 自检 100% 通过
- [ ] 内部审核 100% 通过
- [ ] CNAS 申请书提交
